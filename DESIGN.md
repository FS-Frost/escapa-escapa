# Design Document — Escapa Escapa

## Overview

Pixel-art auto-scroller built with Vite + TypeScript + WebGL2. No game engine and no runtime dependencies. Every visual (sprites, backgrounds, font) and every sound is generated by code. The build is a static site deployed to GitHub Pages.

---

## Architecture

### Canvas vs DOM

- **WebGL2 canvas (CW×270 logical pixels, CW = 320–640)** renders all live gameplay: background, obstacles, player, particles, HUD, radar.
- **DOM overlays** (`position: fixed` over the viewport) render text-heavy menus: main menu, pause, options, game over, victory, high scores, tutorial offer. In portrait a DOM lane pad sits below the canvas.

DOM menus stay accessible and readable at any size; the canvas keeps the pixel look.

### Rendering Pipeline

```
game draw calls (R.rect / R.circle / R.text …)
  └─ batched vertex-colored triangles (one draw call per frame, typically)
       └─ CW×270 offscreen framebuffer (RGBA8, reallocated when CW changes)
            └─ present pass: full-screen triangle, nearest sampling → canvas at device resolution
```

- `Renderer` (`src/gfx/renderer.ts`) exposes a small canvas-like API: `rect`, `strokeRect`, `gradientV`, `tri`, `circle` (sectors too), `radial` (radial gradient rings), `line`, `text`, plus `save/restore/translate` and `alpha`.
- Shapes become triangles in a CPU vertex buffer (position + RGBA). The buffer is flushed when full and at the end of the frame.
- The present pass is the hook for future post-processing (bloom, CRT, etc.).
- WebGL context loss is handled: the renderer skips frames while lost and rebuilds GPU resources on restore.
- Without WebGL2, the game shows a localized "No WebGL2" panel.

### Text

A procedural 5×7 bitmap font (`src/gfx/pixelFont.ts`) is defined as `#`/`.` rows. Each glyph is pre-split into horizontal runs and drawn as rects, so text is crisp at any scale. Accented capitals (Á É Í Ó Ú Ñ Ü) add diacritic pixels above the cap height; lowercase is upcased; unknown characters render as `?`. Text gets a 1-pixel drop shadow by default for contrast.

### Coordinate System & Layout

Logical height is fixed at 270; logical width `CW` adapts. `layout()` (on load, resize and rotation) works on the viewport minus safe-area insets:

- **Landscape** (width ≥ height): `CW = round(270 · aspect)` clamped to [320, 640], scaled to fill. A 19.5:9 phone gets CW ≈ 585 (more road ahead, no black bars); wider than 640 letterboxes.
- **Portrait:** `CW = 320`, the canvas spans the full width at the top (at most 62% of the height), and the lane pad fills the rest.

It then sizes the wrapper in CSS pixels, computes `PAUSE_INSET` (logical px covered by the pause button) and sets the canvas backing store to CSS size × devicePixelRatio (capped at 3). Screen shake is a renderer translation, never a CSS transform.

### Game Loop

```
requestAnimationFrame loop
  ├── update(dt)   — only in STATE.PLAYING
  └── render()     — always (animates the menu background)
```

`dt` is clamped to [0, 0.05] s. All motion is `dt`-scaled.

### Modules & State

All mutable game state lives in one object, `world` (`src/game/world.ts`), shared by the game modules. Entities (obstacles, particles, goal) are plain data with free `update*/draw*` functions; arrays are filtered each frame. No object pooling — entity counts are small.

## State Machine

```
MENU → PLAYING ←→ PAUSED
         ↓
        DEAD → MENU / PLAYING
         ↓
      VICTORY (stages) → next stage / replay / MENU
```

Menu screens (mode select, stage select, skins, options, Fonoteca, tutorial offer) are overlay layers that don't change the state.

`setState()` (`src/ui.ts`) toggles overlay visibility and the wrapper's `.playing` class (which shows the ⏸ button). `Esc` backs out of the innermost layer: menu screens → Fonoteca → install help / tutorial offer → options → pause confirmation → pause toggle.

## Input

- **Touch / mouse:** `pointerdown` anywhere on the page (letterbox bars included) maps the pointer Y to logical Y and jumps to the nearest lane (`laneAtY` → `moveToLane`). Taps on buttons, inputs and overlays are ignored.
- **Keyboard:** `↑`/`Space` and `↓` move one lane from `targetLane`; `P`/`Esc` pause.
- **Portrait pad:** two big buttons, ▲ up and ▼ down, each moving one lane per press (two presses to cross from bottom to top); the button that can't move further is dimmed. Taps below the canvas that miss a button are ignored.
- **Auto-pause:** only when the page is hidden. Rotation re-lays out and the run continues.
- **iOS audio unlock:** `audio.init()` also runs on `pointerup`, since iOS doesn't count `pointerdown` as a user activation.
- **Gestures:** `touch-action: none` and `user-select: none` on the body stop scroll, zoom and selection; overlay panels allow vertical panning.
- **Feedback:** three tabs with a left-pointing chevron on the right edge mark the tappable lanes, and the target lane's tab is lit. Choosing a lane (touch or keyboard) makes its tap zone (`LANE_Y ± LANE_GAP/2`, exactly what `laneAtY` uses) glow for 0.3 s. While jumping, an outline shows where the cube will land.

## Lane System

| Lane | Y (logical px) | Typical hazards |
|------|----------------|-----------------|
| 0 (bottom) | 210 | Zombies, spikes, pits, orbs |
| 1 (mid)    | 160 | Zombies, bats, orbs |
| 2 (top)    | 110 | Bats, ghosts |

A jump interpolates from `fromY` (the Y when the jump started, possibly mid-air) to the target lane's Y with ease-in-out, plus a parabolic arc `-jumpArc · sin(π·t)`. With `span` = vertical distance in lanes (min 0.25):

```
jumpDur = LANE_ANIM_DUR (0.15 s) · √span
jumpArc = LANE_ARC (25 px)       · √span
```

A bottom→top jump takes ≈0.21 s with a higher arc. A new input during a jump restarts the arc from the current Y (no input lock). `player.lane` updates only when the jump lands; collision uses `targetLane`, so lanes crossed in transit never collide.

## Spawner

The spawner is **distance-based and seeded**: a spawn fires each time `worldX` passes `world.nextSpawnX`, and every layout decision draws from the seeded PRNG (`rng.ts`, mulberry32). A seed plus the distance run fully determine the obstacles, independent of frame timing, slow-mo or the player — the daily challenge seeds it from the UTC date.

```
gap (px)  = interval(s) · current speed
interval  = base · difficulty.interval + warm · 0.9 + rand() · 0.3
level     = endless/daily: (e^(worldX/20000) − 1) / (e^2 − 1), capped at 1 (worldX ≥ 40000)
            stage: score / goalScore
base      = stage: 1.1 · stage.interval · (1 − 0.15 · level)     endless/daily: 1.2 − 0.75 · level
interval  ≥ 0.45 s (reaction + longest jump), random part shrinks with level
speed     = endless/daily: base speed · (1 + 1.3 · level) → 2.3× cap     stage: stage.speed · (1 + 0.1 · level)
warm      = max(0, 1 − worldX / 2200)
```

- **Patterns per biome** (`BIOME_PATTERNS`): the classic set plus the biome's mechanic (swoop bats, beams, geysers; the desert mixes all three).
- **Warm-up:** while `warm > 0` (and in stage 1), only single-obstacle patterns spawn.
- **Opening:** each run starts with three simple obstacles already on the road (520 / 780 / 1040 px ahead).
- **Fairness:** a candidate is rejected if, together with obstacles within `speed · 0.5 s + 40 px` of the spawn point, it would cover all three lanes (`laneSet()` counts both lanes of a geyser and a swoop's start and end lanes). Beams use `beamAllowed()`, which predicts what reaches the player when the beam fires. Up to 8 candidates are tried; otherwise it retries 20 px later.
- **Pickups ride along** in a lane the pattern left free: 30% a row of 3 gems, 5% a power-up (after the warm-up). Health orbs (15% while hurt) use `Math.random` so they never shift the seeded sequence.

Obstacles spawn off-screen at `PLAYER_X + SPAWN_AHEAD` (1280 px; the screen ends at CW ≤ 640). The spacing between obstacles depends only on the interval and the speed, so the pace is the same as spawning at the screen edge.

## Modes, Stages & Progression

| Mode | Goal | Layout | Records |
|------|------|--------|---------|
| Stage (8) | After `goalScore` points | Random seed per attempt, one biome | Best stars per stage |
| Endless | None | Random seed; biomes cycle; pace ramps | Top-5 per difficulty + daily best |
| Daily | None | Date seed, normal difficulty | Best per day |

Stages: 1-2 city (stage 1 only single obstacles), 3-4 forest, 5 sky, 6 cave, 7 volcano, 8 desert. Each stage is exponentially harder than the previous: speed ×1.065, interval ×0.93 and goal score ×1.2 per stage (25 → 90 points, 0.95× → 1.48× speed). Multi-obstacle and mechanic patterns get up to 3× likelier as the level rises. A max-level simulation over all biomes found no moment without a free lane. Stars: ★ cleared, ★ no hits, ★ reached ×4. A stage unlocks when the previous one has ≥1 star. JUGAR opens the mode select; the one-time tutorial runs as stage 1.

**Gems & power-ups:** gems collected in a run are banked into the wallet when the run ends (death or victory). Shield absorbs one hit (1 s grace afterwards), magnet pulls gems within 220 px for 8 s, slow-mo scales scroll speed by 0.6 for 5 s (distance-based spawning keeps the layout unchanged).

**Skins:** 8 palettes for the cube (`skins.ts`); some unlock with total stars (4, 9, 15, 24), others are bought with gems (60, 120, 250). Rainbow cycles its hue.

## Difficulty

| | Lives | Orb cap | Speed | Spawn interval |
|---|---|---|---|---|
| Easy | 5 | 5 | 0.85× | 1.2× |
| Normal (default) | 3 | 3 | 1× | 1× |
| Hard | 1 | 2 | 1× | 1× |

Hard is exactly the v1 ruleset, so v1 records live under hard. Records and daily bests are kept per difficulty; the records screen has a tab per difficulty. "Epic comeback" requires winning on the last heart after losing at least one (`hitsTaken > 0`).

## Radar

The 26 px strip at the top maps the distance ahead of the player, `[0, SPAWN_AHEAD]`, to its full width (minus the pause-button corner), so dots enter on the right as obstacles spawn and reach the left edge when they reach the player. That gives ~7 s of warning before an obstacle is on screen at base speed (~3 s at 2.5×). A light band marks the part already visible on screen. The goal beacon stays pinned to the right edge until it is within range. The player's lane is marked on the left edge.

---

## Collision Detection

AABB with an 18% inset on the player rect for forgiving feel. Pits collide only while `targetLane === 0` and score only if the player is out of the bottom lane when they pass. Other obstacles collide only in `targetLane`; obstacles passing in an adjacent lane trigger a near-miss (scared face + blip). After a hit the player is invulnerable for 1.5 s (blinking, gold border). Collision processing stops as soon as the state leaves PLAYING, so one frame can't produce both death and victory.

---

## Scoring & Combo

- Each avoided obstacle scores `comboMultiplier` points.
- Multiplier = `min(4, 1 + floor(streak / 5))`.
- A hit resets streak and multiplier.

---

## Goal Sequence

Only in stages. Endless and daily runs have no goal.

1. At `score ≥ stage.goalScore`, `spawnGoal(15)` places the goal `scrollSpeed · speedBoost · 15 s` ahead. Until then the top bar fills with score / goal score.
2. `speedBoost` ramps toward 2× over 15 s, so the goal arrives a bit sooner.
3. The cue is deliberately quiet:
   - a single `goalAppear` chime when the goal spawns;
   - "¡LA META SE ACERCA!" shows for 2.5 s and fades, leaving a thin progress bar (filled by `1 − (goal.x − player.x) / startDist`) with a small flag under the radar;
   - the music speeds up (up to +25%) and a snare roll grows on top of it (`rushLayer`: 8ths, then 16ths above 60% intensity);
   - soft `countdown` beeps at 3, 2 and 1 seconds from arrival (ETA = distance / current speed).
4. Speed lines appear above 1.6× and a trail above 1.5×.
5. When the goal reaches the player, `triggerVictory()` fires.

## Tutorial

Offered once (the first time JUGAR is pressed, stored in `escapa_tutorial_seen`) and replayable from Options when opened from the main menu. It runs inside a normal PLAYING run with `world.tutorial` set: the spawner is off, avoided obstacles give no score and hits cost no HP. A "Skip tutorial" button is shown while it runs.

| Step | Prompt | Advances when |
|------|--------|---------------|
| up | Tap the top lane (or ↑) | Player lands on lane 2 |
| down | Tap the bottom: you jump straight there (or ↓) | Player lands on lane 0 |
| radar | The radar shows what is coming (arrows point at it; decoys appear) | Any tap/key after 1.2 s; the input doesn't move the player |
| dodge | Dodge the zombie | The practice zombie (spawned on the player's lane) passes; on a hit it respawns after a "try again" message |
| done | Done! Now, escape | 1.8 s later the run resets and the real game starts |

Prompts adapt to the last input kind (`world.inputMode`: touch or keys). Lane steps pulse the target tap zone and, for touch, show a tap ripple.

## Biomes

| Biome | Look | Mechanic |
|-------|------|----------|
| City | Neon buildings, road markings | Classic hazards only |
| Forest | Trees, mushrooms, fireflies | **Swoop bats** (red) switch to an adjacent lane 300 px ahead; the radar draws a line to the target lane |
| Sky | Space, aurora, clouds | **Beams**: a lane blinks for 1.2 s (radar row too), then a laser sweeps it for 0.45 s |
| Cave | Stalactites, glowing crystals | **Darkness**: `R.darkness()` draws a full-screen shader pass that leaves only a flickering light circle around the player; the HUD and radar are drawn after it |
| Volcano | Red sky, volcanoes, falling ash, lava cracks | **Geysers**: smoking vents that erupt 240 px ahead into a lava column blocking two lanes |
| Desert | Dusk dunes, low sun, cacti | **Sandstorms** for 1000 of every 2600 px (by distance): sand covers the road ahead of the player; plus a few swoops, beams and geysers |

Which biome is active: a stage has a fixed one; endless/daily cycle through all six every 4500 px. Each biome is a draw function with parallax multipliers; element counts scale with `CW`. Crossfade: the old biome draws at full alpha and the new one at `alpha = t` over 3 s; darkness and storms are weighted by the same crossfade (`biomeWeight`). The first time a biome appears in a run, a caption announces its name and mechanic, and its music track unlocks in the Fonoteca.

## Audio

All audio is synthesized with Web Audio. The `AudioContext` is created lazily on the first user gesture and suspended while the tab is hidden.

```
theme voices → themeGain[theme] → musicBus → musicFilter (lowpass) → musicGain ┐
sfx voices → sfxGain ────────────────────────────────────────────────────────────┴→ master (mute) → compressor → out
```

### Music

The music is a 16th-note step sequencer over a 4-bar progression, scheduled ahead with a look-ahead timer (25 ms tick, 120 ms window). All progressions are in A minor so themes blend during crossfades.

| Theme | When | BPM | Progression | Character |
|-------|------|-----|-------------|-----------|
| menu | MENU, HISCORE | 92 | Am F C G | Pad, soft triangle bass and arpeggio |
| city | City biome | 116 | Am F C G | Octave saw bass, 16th square arpeggio, four-on-the-floor kick, snare, hats |
| forest | Forest biome | 104 | Am Em F G | Bouncy triangle bass, plucked up/down arpeggio, light kick, shaker |
| sky | Sky biome | 96 | Fmaj7 Em7 Dm7 Cmaj7 | Wide pads, high sine arpeggio in threes, sparse beat |
| cave | Cave biome | 88 | Am G F E | Low drone, echoing plucks, water-drop pings |
| volcano | Volcano biome | 128 | Am G F E | 16th saw bass, pounding kicks, off-beat stabs |
| desert | Desert biome | 108 | Am Dm E Am | Hand drums, swaying snake-charmer melody |

- Every theme has its own gain on one shared step clock. `setMusic(theme, fadeS)` ramps the gains, and the fading theme keeps being scheduled until it's silent.
- Biome changes crossfade over 3 s, matching the visual crossfade; menu ↔ run fades over 0.6 s; music stops (0.3 s) on death and victory, which have their own stinger SFX.
- Pause muffles the music by closing the lowpass filter to 500 Hz.
- During the goal rush, game themes speed up by up to 25% (`intensity = (speedBoost − 1) / 1.5`).
- Music volume uses a squared curve (`(v/100)² · 0.5`); SFX volume is linear.

### SFX

Each SFX schedules `Oscillator → Gain → sfxGain` with an exponential decay.

| Sound | Waveform | Character |
|-------|----------|-----------|
| jump | square, two-tone | Quick ascending chirp |
| hit | sawtooth | Low crunch |
| powerup | sine, 4 notes | Ascending arpeggio |
| death | sawtooth, 4 notes | Descending fall |
| victory | sine, 6 notes + chord | Fanfare |
| pass | square | Tiny blip |
| goalAppear | triangle, 3 notes | Soft rising chime, once |
| countdown | sine | Soft beep at 3-2-1 s before the goal |
| beamCharge | saw + sine rising | Beam starts charging |
| beamFire | noise sweep + square drop | Beam fires |
| swoop | triangle glide down | Red bat switches lane |
| geyser | low noise swell + sub drop | Geyser erupts |
| storm | slow noise swell | Sandstorm rolls in |
| combo | sine, two-tone | Shine |
| nearMiss | sine | Subtle blip |
| achievement | sine, 3 notes | Unlock jingle |

## Fonoteca (jukebox)

Opened from the main menu ("🎵 FONOTECA"). It lists the four themes; Menu and City are available from the start, and Forest and Sky unlock the first time their biome is reached (stored in `escapa_music_unlocked`; locked tracks show "??? · reach the …").

- **Play / pause:** tap a track to play it (crossfade); the button pauses (music fades out) and resumes.
- **Rush mode:** plays the track at goal-rush intensity (+25% tempo and the growing snare roll).
- **Visualizer:** 16 pixel bars driven by an `AnalyserNode` on the music bus (post volume), sampled on a roughly logarithmic frequency scale.
- **Continuous play:** after 4 loops of a track it moves on to the next unlocked one (`audio.onLoop`).

Closing it (button or Esc) resets intensity and returns to the menu theme.

## Haptics

`navigator.vibrate` patterns for jump, hit, death, power-up, combo, achievement and victory. They fire only if the option is on and the API exists. iOS Safari has no Vibration API, so the option is hidden there.

## Internationalization

`src/i18n.ts` holds `es` and `en` dictionaries with identical keys (the `en` type is derived from `es`, so a missing key fails the build). The initial language comes from `navigator.language` and can be changed in Options. DOM text uses `data-i18n*` attributes refreshed by `applyDomI18n()`; canvas text calls `t()` each frame. Player-facing names come from `displayName()` (entered name or the localized "Jugador"/"Player").

## Mobile

- Both orientations; see Coordinate System & Layout. Rotating mid-run keeps playing.
- DOM menus use `rem` sizes on a fluid root font size and switch to two columns (`.cols`) on short landscape screens, so they fit without scrolling. Keyboard hints are hidden on touch-only devices.
- Small canvas HUD text is drawn at `UI_SCALE` (2× on phones) with `maxWidth` auto-shrink.

## PWA

- `scripts/pwa-plugin.ts` runs at build time. It draws the icons from code (the player cube on a dark background, 192/512 px, a maskable 512 and a 180 px Apple touch icon), encodes them as PNG with a small built-in encoder (zlib), and emits `manifest.webmanifest` (fullscreen, any orientation) and `sw.js`.
- `sw.js` precaches the exact build output. Page loads are network-first (updates arrive) with the cached shell as offline fallback; other assets are cache-first. The cache name is a hash of the build, so a new deploy installs a fresh cache and drops the old one.
- `src/pwa.ts` registers the service worker (production only) and drives the install button: Chromium's `beforeinstallprompt` is deferred and replayed from "📲 Instalar app"; on iOS Safari the button opens Add-to-Home-Screen steps; nothing is shown when already installed.
- The layout respects safe-area insets (`viewport-fit=cover` + body padding).
- The pause button grows to 44 px on coarse pointers; the HUD hearts and the radar scale end left of it (`PAUSE_BTN_INSET`).

## Known Trade-offs

- **No object pooling:** fine at this entity density.
- **Background redrawn every frame:** cheap in a single batched draw call.
- **Biome layers baked into one function per biome:** simple, but adding layers means editing the function.
- **Canvas text is the pixel font only:** emoji and unsupported glyphs render as `?` on canvas (they're fine in DOM menus).
- **Daily best uses the UTC date**, kept for v1 compatibility.
