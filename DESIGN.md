# Design Document — Escapa Escapa

## Overview

Pixel-art auto-scroller built with Vite + TypeScript + WebGL2. No game engine and no runtime dependencies. Every visual (sprites, backgrounds, font) and every sound is generated by code. The build is a static site deployed to GitHub Pages.

---

## Architecture

### Canvas vs DOM

- **WebGL2 canvas (480×270 logical pixels)** renders all live gameplay: background, obstacles, player, particles, HUD, radar.
- **DOM overlays** (`position: absolute` over the canvas) render text-heavy menus: main menu, pause, options, game over, victory, high scores, plus the portrait "rotate" notice.

DOM menus stay accessible and readable at any size; the canvas keeps the pixel look.

### Rendering Pipeline

```
game draw calls (R.rect / R.circle / R.text …)
  └─ batched vertex-colored triangles (one draw call per frame, typically)
       └─ 480×270 offscreen framebuffer (RGBA8)
            └─ present pass: full-screen triangle, nearest sampling → canvas at device resolution
```

- `Renderer` (`src/gfx/renderer.ts`) exposes a small canvas-like API: `rect`, `strokeRect`, `gradientV`, `tri`, `circle` (sectors too), `radial` (radial gradient rings), `line`, `text`, plus `save/restore/translate` and `alpha`.
- Shapes become triangles in a CPU vertex buffer (position + RGBA). The buffer is flushed when full and at the end of the frame.
- The present pass is the hook for future post-processing (bloom, CRT, etc.).
- WebGL context loss is handled: the renderer skips frames while lost and rebuilds GPU resources on restore.
- Without WebGL2, the game shows a localized "No WebGL2" panel.

### Text

A procedural 5×7 bitmap font (`src/gfx/pixelFont.ts`) is defined as `#`/`.` rows. Each glyph is pre-split into horizontal runs and drawn as rects, so text is crisp at any scale. Accented capitals (Á É Í Ó Ú Ñ Ü) add diacritic pixels above the cap height; lowercase is upcased; unknown characters render as `?`. Text gets a 1-pixel drop shadow by default for contrast.

### Coordinate System & Layout

Fixed logical resolution of 480×270 (16:9). `layout()` fits the game into the viewport minus safe-area insets, sizes the wrapper in CSS pixels, and sets the canvas backing store to CSS size × devicePixelRatio (capped at 3). Screen shake is a renderer translation, never a CSS transform.

### Game Loop

```
requestAnimationFrame loop
  ├── update(dt)   — only in STATE.PLAYING
  └── render()     — always (animates the menu background)
```

`dt` is clamped to [0, 0.05] s. All motion is `dt`-scaled.

### Modules & State

All mutable game state lives in one object, `world` (`src/game/world.ts`), shared by the game modules. Entities (obstacles, particles, goal) are plain data with free `update*/draw*` functions; arrays are filtered each frame. No object pooling — entity counts are small.

## State Machine

```
MENU → PLAYING ←→ PAUSED
         ↓
        DEAD → MENU / PLAYING
         ↓
      VICTORY → HISCORE (after 2.5 s) → MENU
```

`setState()` (`src/ui.ts`) toggles overlay visibility and the wrapper's `.playing` class (which shows the ⏸ button). The options panel is a separate layer above MENU or PAUSED and does not change the state. `Esc` backs out of the innermost layer: options → pause confirmation → pause toggle.

---

## Input

- **Touch / mouse:** `pointerdown` anywhere on the page (letterbox bars included) maps the pointer Y to logical Y and jumps to the nearest lane (`laneAtY` → `moveToLane`). Taps on buttons, inputs and overlays are ignored.
- **Keyboard:** `↑`/`Space` and `↓` move one lane from `targetLane`; `P`/`Esc` pause.
- **Auto-pause:** when the page is hidden, or a touch device rotates to portrait.
- **iOS audio unlock:** `audio.init()` also runs on `pointerup`, since iOS doesn't count `pointerdown` as a user activation.
- **Gestures:** `touch-action: none` and `user-select: none` on the body stop scroll, zoom and selection; overlay panels allow vertical panning.

## Lane System

| Lane | Y (logical px) | Typical hazards |
|------|----------------|-----------------|
| 0 (bottom) | 210 | Zombies, spikes, pits, orbs |
| 1 (mid)    | 160 | Zombies, bats, orbs |
| 2 (top)    | 110 | Bats, ghosts |

A jump interpolates from `fromY` (the Y when the jump started, possibly mid-air) to the target lane's Y with ease-in-out, plus a parabolic arc `-jumpArc · sin(π·t)`. With `span` = vertical distance in lanes (min 0.25):

```
jumpDur = LANE_ANIM_DUR (0.15 s) · √span
jumpArc = LANE_ARC (25 px)       · √span
```

A bottom→top jump takes ≈0.21 s with a higher arc. A new input during a jump restarts the arc from the current Y (no input lock). `player.lane` updates only when the jump lands; collision uses `targetLane`, so lanes crossed in transit never collide.

## Spawner

Weighted random pattern selection over `SPAWN_PATTERNS`. The spawn interval shrinks with score: `interval = max(0.45, 1.2 − score·0.005) + random(0..0.3)`. If HP is below max, there is a 15% chance to spawn a Big M Orb instead.

---

## Collision Detection

AABB with an 18% inset on the player rect for forgiving feel. Pits collide only while `targetLane === 0` and score only if the player is out of the bottom lane when they pass. Other obstacles collide only in `targetLane`; obstacles passing in an adjacent lane trigger a near-miss (scared face + blip). Invincibility lasts 1.2 s after a hit. Collision processing stops as soon as the state leaves PLAYING, so one frame can't produce both death and victory.

---

## Scoring & Combo

- Each avoided obstacle scores `comboMultiplier` points.
- Multiplier = `min(4, 1 + floor(streak / 5))`.
- A hit resets streak and multiplier.

---

## Goal Sequence

1. At `score ≥ 100`, `spawnGoal()` places the goal `scrollSpeed · speedBoost · 30 s` ahead.
2. `speedBoost` ramps toward 2.5× over 30 s, so the goal arrives a bit sooner than 30 s.
3. An alarm plays every second after 3 s; speed lines appear above 1.6× and a trail above 1.5×.
4. When the goal reaches the player, `triggerVictory()` fires.

## Biomes

| Biome | Threshold | Palette |
|-------|-----------|---------|
| City  | 0  | Dark blue sky, neon buildings, yellow road markings |
| Forest | 34 | Dark green, trees, mushrooms, fireflies |
| Sky   | 67 | Deep space, aurora bands, blinking stars, cloud floor |

Each biome is a draw function with hardcoded parallax multipliers. Crossfade: the old biome draws at full alpha and the new one at `alpha = t` over 3 s. City window lights come from a deterministic hash, so they don't flicker.

## Sprites

Drawn with rects on a 2×2 "art pixel" grid (`P = 2`) after translating to the sprite origin.

| Sprite | Art size | Notes |
|--------|----------|-------|
| Player | 9×9 | 5 expressions; shine/shadow edges; gold border with shield |
| Zombie | 6×10 | 2-frame walk |
| Spike | 8×8 | Two spikes with shine |
| Bat | 10×7 | 2-frame wing flap |
| Ghost | 8×9 | 75% alpha, wavy bottom |
| Big M Orb | — | Radial glow + disc + pixel-font "M" |
| Goal flag | — | Pole, flag, pixel-font ★ |

## Particles

Square particles that fade over their life (`src/game/particles.ts`).

| Type | Trigger | Visual |
|------|---------|--------|
| Sparkles | Obstacle avoided / orb | Gold pixels bursting outward with gravity |
| Hit stars | Player hit | White/pink pixels |
| Trail | High speed (goal approach) | Fading purple squares behind the player |
| Lane arc | Lane change | Pink pixels along the jump path |

## Audio

Web Audio synthesis: each SFX schedules `Oscillator → Gain → master gain` with an exponential decay. The `AudioContext` is created lazily on the first user gesture; the master gain implements volume and mute.

| Sound | Waveform | Character |
|-------|----------|-----------|
| jump | square, two-tone | Quick ascending chirp |
| hit | sawtooth | Low crunch |
| powerup | sine, 4 notes | Ascending arpeggio |
| death | sawtooth, 4 notes | Descending fall |
| victory | sine, 6 notes + chord | Fanfare |
| pass | square | Tiny blip |
| goalAlarm | square, two-tone | Alert |
| combo | sine, two-tone | Shine |
| nearMiss | sine | Subtle blip |
| achievement | sine, 3 notes | Unlock jingle |

## Haptics

`navigator.vibrate` patterns for jump, hit, death, power-up, combo, achievement and victory. They fire only if the option is on and the API exists. iOS Safari has no Vibration API, so the option is hidden there.

---

## Internationalization

`src/i18n.ts` holds `es` and `en` dictionaries with identical keys (the `en` type is derived from `es`, so a missing key fails the build). The initial language comes from `navigator.language` and can be changed in Options. DOM text uses `data-i18n*` attributes refreshed by `applyDomI18n()`; canvas text calls `t()` each frame. Player-facing names come from `displayName()` (entered name or the localized "Jugador"/"Player").

## Options

Shared panel reachable from the main menu and the pause menu:

| Option | Effect |
|--------|--------|
| Language | es / en |
| Volume / Mute | Master gain |
| Vibration | Haptics on/off (hidden without API) |
| Show radar | Radar strip |
| Reduce motion | Disables screen shake, hit flash, speed lines; default follows `prefers-reduced-motion` |
| Fullscreen | Fullscreen API + landscape lock on Android (hidden where unsupported) |

Pause also offers resume, restart and back-to-menu (both destructive actions ask for confirmation), plus collapsible controls help.

## Persistence (localStorage)

| Key | Contents |
|-----|----------|
| `escapa_playername` | Raw entered name |
| `player2_hiscores` | Top 5 `{ name, score, stats, date }`, sorted desc |
| `player2_daily` | `{ "YYYY-MM-DD": bestScore }` (UTC date) |
| `player2_achievements` | `{ achievementId: timestamp }` |
| `player2_options` | `{ volume, showRadar, mute, lang, vibration, reduceMotion }` |

Keys are unchanged from v1. Options missing newer fields fall back to defaults. All access is wrapped in try/catch so the game degrades silently in private browsing. Record names are rendered with `textContent`, never `innerHTML`.

## Mobile

- Landscape 16:9 only; portrait on touch devices shows a rotate notice (CSS media query) and auto-pauses.
- The layout respects safe-area insets (`viewport-fit=cover` + body padding).
- The pause button grows to 44 px on coarse pointers; the HUD hearts sit left of it.

## Known Trade-offs

- **No object pooling:** fine at this entity density.
- **Background redrawn every frame:** cheap in a single batched draw call.
- **Biome layers baked into one function per biome:** simple, but adding layers means editing the function.
- **Canvas text is the pixel font only:** emoji and unsupported glyphs render as `?` on canvas (they're fine in DOM menus).
- **Daily best uses the UTC date**, kept for v1 compatibility.
