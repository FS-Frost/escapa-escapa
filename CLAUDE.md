# CLAUDE.md — Escapa Escapa

## Project at a Glance

Pixel-art auto-scroller. Vite + TypeScript + WebGL2 (own shaders, no engine, no runtime dependencies). Everything visual and audible is generated by code — no image or sound files.

```
npm install
npm run dev       # dev server, --host so phones on the LAN can connect
npm run build     # tsc --noEmit + vite build → dist/
npm run preview   # serve dist/
```

Deploy: `.github/workflows/deploy.yml` builds and publishes to GitHub Pages on every push to `main` → https://fs-frost.github.io/escapa-escapa/. `vite.config.ts` uses `base: './'` so the build works under the Pages sub-path.

PWA: `scripts/pwa-plugin.ts` (Vite plugin) draws the app icons from code (the player cube), encodes them as PNG, and emits `manifest.webmanifest` and `sw.js` with the exact build output to precache (cache version = hash of the build). The dev server serves the manifest and icons; the service worker is only registered in production (`src/pwa.ts`). Never commit icon files.

## Rendering

- Everything is drawn through `R` (`src/gfx/renderer.ts`) into a CW×270 framebuffer (CW follows the screen aspect), then a present pass upscales it to the screen with nearest filtering. Post-processing effects belong in that present pass (`PRESENT_FS`).
- `R` is canvas-like but minimal: `save/restore/translate` and `R.alpha` (multiplied into every draw). No rotation/scale.
- **Logical size:** height is always `CH = 270`; width `CW` is set by `layout()` (`main.ts`) from the screen aspect, clamped to `[MIN_CW, MAX_CW]` = [320, 640] (320 in portrait). `CW`, `PORTRAIT` and `PAUSE_INSET` are `export let` live bindings updated on resize/rotation: always read them at runtime, never cache them in module-level constants. Anything spanning the screen must scale with `CW` (e.g. `fill()` counts in `biomes.ts`).
- Text is **only** the pixel font via `R.text(str, x, y, color, { scale, align, baseline, shadow, maxWidth })`. Small HUD text uses `scale: UI_SCALE` (2 when a logical pixel is under 2.2 CSS px, i.e. phones) and `maxWidth` so it shrinks instead of overflowing. Unknown characters render as `?`; add glyphs to `pixelFont.ts` (emoji are not supported on canvas — use them only in DOM).

## Important Invariants

- **`world.player` must exist before the loop starts.** `world.ts` initializes it with `createPlayer()`; `startGame()` replaces it.
- **`render()` runs in all states** (it animates the menu background). Player/obstacle drawing is guarded by `PLAYING || PAUSED`.
- **`update(dt)` only runs in `STATE.PLAYING`.**
- **`dt` is capped at 0.05 s.** All motion must be `dt`-scaled — never assume 60 fps.
- **`player.targetLane`** is the lane being moved to; **`player.lane`** lags until the jump lands. Collision and expression logic use `targetLane`. Obstacles in lanes crossed mid-jump never collide.
- **Retargeting mid-jump is allowed:** `moveToLane()` restarts the arc from the current Y (`fromY`); there is no input lock. Jump duration and arc height scale with √(distance in lanes).
- **`obs.passed` / `obs.scored`** prevent double-counting.
- **Obstacles spawn off-screen at `PLAYER_X + SPAWN_AHEAD`** and the radar maps exactly `[player.x, player.x + SPAWN_AHEAD]` to its width, so it previews what is coming. Change both together via `SPAWN_AHEAD`.
- **The DOM pause button covers the top-right corner** while playing: keep canvas HUD out of the last `PAUSE_INSET` logical px (computed in `layout()` from the button size and CSS scale).
- **State changes go through `setState()`** (`ui.ts`); it toggles overlays, the `.playing` class, resets the pause confirmation and closes options when play resumes.
- **All UI text goes through i18n.** DOM uses `data-i18n`, `data-i18n-placeholder`, `data-i18n-aria`; canvas uses `t()`. Every key must exist in both `es` and `en` (`en` is typed as `Record<Key, string>`, so a missing key fails the build).
- **Player name:** `world.playerName` is the raw input (may be empty); display it with `displayName()`, which falls back to the localized default.
- **Respect options:** `world.opts.reduceMotion` disables shake, hit flash and speed lines; haptics only fire if `opts.vibration` and the API exists.

## Design Decisions

- **DOM UI scales with the screen:** sizes are in `rem` on a fluid root size (`clamp(16px, 2.2vmin + 8px, 22px)`); buttons are ≥ 44 px. Panels group content in `.cols > .col`, stacked by default and side by side on short landscape screens (`max-height: 560px`). Keyboard-only hints carry `.hint-keys` (hidden on touch-only devices); `.hint-portrait` only shows in portrait.
- **Install offer:** "📲 Instalar app" in the main menu appears only when installable (Chromium `beforeinstallprompt`) or on iOS Safari (opens Add-to-Home-Screen help); hidden when already installed.

- **Touch input = tap-to-lane:** `pointerdown` anywhere on the page (letterbox bars included) jumps to the lane nearest to the touch Y. No swipe/drag. Keyboard ↑/Space/↓ steps one lane.
- **Control feedback:** right-edge lane tabs (target lane lit), a brief glow over the chosen lane's tap zone (`world.laneFlash`, set in `moveToLane`) and a landing outline while jumping. On-screen buttons only in portrait (the lane pad).
- **Tutorial:** offered once, the first time JUGAR is pressed (`escapa_tutorial_seen`), and replayable from Options when it was opened from the menu. It runs inside a normal PLAYING run with `world.tutorial` set: the spawner is off, avoided obstacles give no score and hits cost no HP (`logic.ts` routes them to `tutorial.ts`). Input during the radar step only advances the step (`tutorialConsumesInput`). Prompts use `world.inputMode` (`touch` | `keys`, last input kind).
- **Goal cue is quiet on purpose:** one `goalAppear` chime, a 2.5 s notice that fades into a progress bar, a snare roll layered on the music (`rushLayer`, grows with intensity) and soft 3-2-1 `countdown` beeps. Never reintroduce a repeating alarm.
- **Orientation:** both work and rotating mid-run just re-lays out (no pause). Landscape: the world widens to fill the screen. Portrait: game view on top (320×270) and a three-button lane pad below (`#touch-pad`, `.pad-btn[data-lane]`); taps below the canvas belong to the pad. Overlays are `position: fixed` so menus fit either way. The run auto-pauses only when the tab is hidden.
- **Difficulty:** `RULES` in `difficulty.ts` — easy 5 lives / 0.85× speed / 1.2× interval, normal 3 lives, hard 1 life (orb can raise to 2 = the original v1 rules). Health orbs refill up to `maxHp`. 1.5 s blinking grace period after a hit.
- **Modes:** `startGame({ mode, stageId?, tutorial? })`. *Stage*: one biome, goal after `goalScore` points (15 s rush), 1-3 stars (cleared / no hits / ×4 combo), next stage unlocks with ≥1 star. *Endless*: no goal, biomes cycle every `BIOME_LEN` px and pace/speed ramp over `RAMP_DIST`; owns the records tables. *Daily*: endless with a date seed (`stringSeed(todayKey())`) and normal difficulty, best per day. JUGAR opens the mode select (after the one-time tutorial offer); the tutorial runs as stage 1.
- **Spawner is distance-based and seeded:** it fires when `worldX` passes `world.nextSpawnX`, and every layout decision uses `rand()` from `rng.ts`, so a seed + distance fully determine the obstacles (daily challenge). Things that depend on the player (health orbs) use `Math.random` and never consume the seeded sequence; slow-mo changes time, not distance. Warm-up (first `WARMUP_DIST` px) spawns single obstacles further apart; runs start with three easy obstacles (`seedOpening`); a pattern is rejected if, within `FAIR_WINDOW_S` of travel around the spawn point, it would leave no free lane (`laneSet()` counts every lane an obstacle may occupy).
- **One mechanic per biome:** forest = `swoop` bats that switch lane `SWOOP_AT` px ahead (radar draws the switch); sky = beams that blink for `BEAM_CHARGE` s then sweep a lane; cave = `R.darkness()` light circle around the player (shader, HUD stays lit); volcano = `geyser` vents that erupt `GEYSER_AT` px ahead and block two lanes; desert = sandstorms by distance (`stormPhase`) plus a bit of everything. A biome's first appearance in a run shows a caption with its name and mechanic.
- **Pickups never block lanes** (`isPickup`): orb (+1 heart), gem (currency, banked into `escapa_gems` when the run ends), power (shield absorbs one hit; magnet pulls gems 8 s; slow-mo 0.6× scroll 5 s).
- **Skins** are palettes for `drawPlayer`, unlocked by total stage stars or bought with gems (`skins.ts`).
- **Targets:** Android Chrome + iOS Safari. iOS has no Vibration API (option hidden) and no element fullscreen on iPhone (button hidden). iOS unlocks audio on `pointerup`/`click`, not `pointerdown`.
- **Phases:** Phase 1 (port + touch + deploy + i18n/options) is done, plus music, radar look-ahead, control feedback, tutorial, adaptive layout, PWA, Fonoteca, modes/stages/daily, six biomes with mechanics, pickups and skins. Next ideas: more stages, bosses, post-processing in the present pass.
- **Persistence:** localStorage keys from v1 are kept forever; new option fields fall back to defaults when missing.

## Adding a New Obstacle Type

1. Add a draw function in `sprites.ts`.
2. Add the type to `ObsType` and to `OBS_W`, `OBS_H`, `OBS_YOFF` in `obstacles.ts`; add a `case` in `drawObstacle()` (and motion in `updateObstacle()` if needed).
3. Add a `RADAR_COLORS` entry in `hud.ts` (and a custom radar mark if it spans lanes).
4. Add weighted pattern(s) to `BASE_PATTERNS` or a biome's list in `BIOME_PATTERNS`; use `rand()`/`randInt()`, never `Math.random`, so seeded layouts stay deterministic.
5. If it occupies more than one lane, extend `laneSet()` so fairness checks see it; if it's a pickup, add it to `isPickup()`.

## Adding a New Achievement

1. Add the id to `AchievementId` in `logic.ts`.
2. Add `ach.<id>` to both dictionaries in `i18n.ts`.
3. Call `achievementsCheck('<id>')` at the event site. Banner, storage, sound and vibration are automatic.

## Adding a New Biome

1. Add `{ name }` to `BIOMES` in `biomes.ts`, write `drawMyBiome(off)` and register it in `DRAW`.
2. Add its pattern list to `BIOME_PATTERNS` (same index) with its mechanic.
3. Add a music theme (`MusicSection`, `THEMES`, `playStep` case) and a Fonoteca track (`TRACKS` in `jukebox.ts`).
4. Add i18n keys `biome.<name>`, `mech.<name>`, `track.<name>`, `juke.locked<Name>`, and optionally a stage in `STAGES`.
5. Crossfade, parallax, endless cycling, captions and track unlock are automatic.

## Adding a Stage / Skin

- Stage: append to `STAGES` (`stages.ts`) with `biome`, `goalScore`, `speed`, `interval`, and add `stage.<id>` to i18n. Stars, unlocking and the select grid are automatic.
- Skin: append to `SKINS` (`skins.ts`) with colors and `stars` or `gems`, and add `skin.<id>` to i18n.

## Adding a String / Language

- String: add the key to `es` and `en` in `i18n.ts`, then use `t('key', { vars })` or `data-i18n="key"`.
- Language: add a dictionary with the same keys, register it in `DICTS` and `LANGS`, and extend `Lang`. Check the pixel font covers its characters.

## Audio & Haptics

- SFX live in `sounds` (`audio.ts`): closures calling `tone(freq, dur, wave, vol, delay)`. Play with `audio.play('name')`.
- The `AudioContext` is created lazily on the first user gesture (`audio.init()`); never at module load.
- Music: themes `menu | city | forest | sky` in `THEMES` (bpm + 4-bar progression, all in A minor) with per-theme patterns in `playStep()`. All themes share one 16th-note step clock (look-ahead scheduler), so `audio.setMusic(theme, fadeS)` crossfades in time.
- Who sets the music: `setState()` (`ui.ts`) → menu theme on MENU/HISCORE, biome theme in a run (muffled while PAUSED), silence on DEAD/VICTORY. `update()` follows the biome (`biomeTheme()`, 3 s crossfade) and raises tempo with the goal rush (`setIntensity`).
- Adding a biome theme: add it to `MusicSection`/`THEMES` and a `case` in `playStep()`; the name must match the biome name. Also add it to `TRACKS` in `jukebox.ts` (+ `track.*` / lock-hint i18n keys).
- Fonoteca hooks: `audio.onLoop(cb)` fires when the 4-bar loop wraps (continuous play switches track every `LOOPS_PER_TRACK` loops); `audio.getSpectrum(buf)` reads an `AnalyserNode` on the music bus (visualizer). Intensity is reset to 0 outside a run (`syncMusic`), so the jukebox rush toggle and the game don't leak into the menu.
- Vibration patterns live in `PATTERNS` (`haptics.ts`); play with `haptics.play('name')`.

## localStorage Keys

| Key | Purpose |
|-----|---------|
| `escapa_playername` | Last entered player name (plain string, may be empty) |
| `escapa_tutorial_seen` | `'1'` once the tutorial was offered (accepted, skipped or finished) |
| `escapa_stage_stars` | `{ stageId: bestStars }` |
| `escapa_gems` | Gem wallet (number) |
| `escapa_skin` / `escapa_skins_owned` | Selected skin id / ids bought with gems |
| `escapa_daily_challenge` | Daily challenge best by `YYYY-MM-DD` (UTC) |
| `escapa_music_unlocked` | Fonoteca tracks unlocked, default `["menu","city"]`; a biome's theme unlocks when the biome is first reached (`updateBiomes`) |
| `player2_hiscores` / `player2_hiscores_easy` / `player2_hiscores_normal` | Top-5 `{ name, score, stats, date }` per difficulty; the unsuffixed key is **hard** (v1 records were played with hard rules) |
| `player2_daily` (+ `_easy` / `_normal`) | Daily best by `YYYY-MM-DD` (UTC) key, per difficulty (unsuffixed = hard) |
| `player2_achievements` | Unlocked achievement timestamps |
| `player2_options` | `{ sfxVolume, musicVolume, showRadar, mute, lang, vibration, reduceMotion, difficulty }` (a v1 `volume` field migrates to `sfxVolume`) |

All access goes through `storage.ts`. Never call `localStorage` directly elsewhere.

## Pixel Art Conventions

- `P = 2` — one art pixel = 2×2 logical pixels. Sprites use `px(col, row, w, h, color)` after `R.translate()` to the sprite origin.
- Logical height is always 270 (width varies, see Rendering); the present pass uses nearest filtering. Never add smoothing.

## Testing Tips

- In `npm run dev`, game modules can be imported from the page (`await import('/src/game/world.ts')`) to set up states (score, goal, obstacles) for manual or headless testing.
- Kill stale dev servers before starting a new one: after HMR, a stale server serves modules with different `?t=` URLs, so imported `world` would be a different instance.
